## 1. 조기 폐기 (사전등록 재앙 기준 — 이것 외의 폐기는 없다)

arm은 다음 중 하나가 **forward 표본**에서 성립하면 관제 페이지에서 `retired`로 처리할 수 있다.
1. 정산 30건 이상에서 paired 알파(같은 세션·같은 K 풀 기대값 대비) 평균 ≤ −2.0%/건
2. funded 북 MaxDD > 20%
3. 운영 결함: 격리 위반(integrity FAIL) 또는 장부 대사 불일치가 연속 3영업일 미해결
4. 유령 vs 일봉 괴리(`phantom_vs_daily`)의 net 차 평균이 정산 20건 이상에서 ≤ −1.5%p (실행 현실이 이론값을 삼키는 arm)

폐기는 다중검정을 **줄이므로** 언제든 안전하다. 폐기 arm은 원장 보존, 신규 진입 0, 판정(max-stat)에서 제외.
`paused`는 폐기가 아니다: 신규 진입만 멈추고 보유분 정산·판정 포함은 유지(운영 점검·시세 부하 조정용).

## 2. 개선 = 새 arm id (V2)

파라미터·규칙·출구·픽 순서 등 계약에 닿는 변경은 **새 id**(`<arm>_v2` 등)로 forward 0에서 시작한다. 원본은 폐기 또는
병행. 기존 표본을 새 규칙으로 재해석하지 않는다(= 골대 이동). 새 arm은 소속 family의 내부 multiplicity에 들어간다.

## 3. 신규 편입 = 새 family

새 가설(F1 숏, F2 페어, TSMOM, 운영자 아이디어)은 별도 family로 등록하고 family 간 Holm에 자동 포함된다.
F0 안에 변형을 더 넣는 것은 금지 유지(12/16이 이미 한 베팅).

## 4. 관제 제어의 범위

관제 페이지(`/strategy` 인큐베이터 절)가 할 수 있는 것: `paused` / `retired` / `active` 전환 + 메모. 모든 전환은
`data/shadow/control_tower_audit.jsonl`에 감사 기록. **승격·env 원복·재시작은 UI에 없다** — 게이트 판정 후 운영자 절차.
