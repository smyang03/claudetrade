# 설계 v0: green-tape 조건부 용량 — 계측 우선 (2026-07-09)

지시: "분별력 없이 뭘 보고 수익 내나 → 창구 수확 극대화(P1) 설계 진행" (운영자 승인).
성격: **shadow/계측 단계.** enforce 아님. 라이브 변경 = 로그·funnel 이벤트 1건 추가뿐.

## 1. 문제 (실측)

- 시스템의 유일 실측 수익원 = 창구일 tail 수확(4/28·5/7·6/17). rule_direct 전환 후 진입 플랜 생산 = early_judge 단독, **세션 캡 10콜 — 매일 소진**(exhausted 로그 30~59회/일 실측).
- 창구일이든 평일이든 캡이 같음 → 창구일에 수확 후보가 캡에 버려질 구조적 위험(완결성 토론 P1).

## 2. 캘리브레이션 결과 — ★단일 실시간 신호 확립 실패 (정직 기록)

창구일 3회의 관측 가능 신호 실측:

| 신호 후보 | 4/28 | 5/7 | 6/17 | 판정 |
|---|---|---|---|---|
| KODEX200 intraday | **−0.15%** | +0.27% | +3.15% (p90) | 6/17만 분리 — 2/3 미스 |
| 선정행 hot비율(chg≥8) | 59% | 61% | 1.7% | 4/28·5/7만 분리 — 반대 반쪽 |
| 선정행 수 | 27 | 51 | 300 | 월별 로깅 밀도 confound — 사용 불가 |

→ "지수 green이면 캡 확장" 같은 단순 임계는 창구일 2/3을 놓친다. **임계를 지금 pre-register하는 것은 데이터 위반** — 계측이 먼저다.

## 3. v0 구현 (이번 커밋)

- **부분 절삭**: 기존 계측 재사용 — `early_judge_trigger_eval` funnel 이벤트의 `reason=run_cap_reached` (이미 기록 중).
- **전량 스킵**(capacity=0 조기 return, 기존 미계측): `early_judge_capacity_dropped` funnel 이벤트 + `[green_tape_shadow]` 로그 신설 — 버려진 후보 티커·가격 기록 (trading_bot.py maybe_run_early_judge_triggers).
- 라이브 행동 변화 0 (로그·이벤트만).

## 4. 판독(다음 단계, 표본 도착 후)

`tools/green_tape_capacity_review.py`(작성 예정): dropped 후보의 사후 MFE/우리규칙 net(분봉) ×
당시 시장 상태(지수 tape·hot비율·요일)를 조인 — **"캡이 버린 후보가 돈이었나, 언제 그랬나"**를
데이터가 답하게 함. 임계·확장폭(10→N)은 이 판독에서 도출.

## 5. pre-registered 판정 (enforce 조건)

- dropped 표본 **n≥30** + **창구성 날 2회 이상 포함**에서, dropped 후보의 우리규칙 근사 net이
  특정 관측 상태(판독이 찾은 조건)에서 **월별 방향 일치 양수**면 → 조건부 캡 확장(EARLY_JUDGE_
  GREEN_TAPE_* 토글, 기본 off) 설계 착수.
- 반대로 dropped net이 전 상태 음수면 → 캡 10 유지 확정(용량이 아니라 후보질 문제로 종결).

## 6. 안전

- red-tape와 독립(방어 게이트 무접촉). 구매력 게이트 뒤에 위치(살 수 없으면 애초에 콜 없음).
- 기록 실패는 전부 fail-open(try/except) — 진입 경로 무영향.

— 근거 실측: 창구일 지수/후보압력 대조(세션 기록), exhausted 빈도, 완결성 토론 P1.
