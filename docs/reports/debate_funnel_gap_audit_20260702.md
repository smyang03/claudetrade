# 퍼널 완전성 감사(gap audit) 토론 판정 (2026-07-02)

**명제**: "퍼널 3단(①후보군 선정 ②매수 실행 ③매도/출구)에 아직 검토·측정조차 되지 않았으면서 net에 유의미할 수 있는 노드(갭)가 최소 1개 존재한다."
**형식**: PRO(갭 헌터, 시드 11) vs CON(영수증 검사관, 보고서 ~120건·도구 172개 원장) → 상호 반박 → 사회자 직접 검증 3건. 목적=미검토 노드 발굴이지 기각 레버 재론 아님. 전 과정 read-only.

## 최종 판정: **명제 성립 (찬성)** — 단 생존 갭은 전부 "측정 대상"이지 행동 레버가 아님

양측 최종 입장이 사실상 수렴: PRO 3개 유지 → CON "1.5개 생존+위생 1건" 인정. 사회자 판정은 아래 표.

## 2. 사회자 직접 검증 3건 (구속)
1. `MAX_SECTOR_POSITIONS` repo 전수 grep → 참조 1줄(로드만) 확정.
2. profit_review 트리거→sell_order_sent: US n=39 중앙 903s/p90 1851s/max 63,037s, KR n=6 중앙 1051s 재현.
3. `evidence_ceiling_applied` 실기록 확인: US 1=38/0=21,930/None=69,369 · KR 1=3/0=11,981/None=25,305 — CON 수치 정확, PRO 필드 착오 확정. None 다수+프롬프트 자기검열 비가시성은 잔여 미측정.

## 3. 공통 한계 (판정문 고정)
- 생존 갭 G1·G2 모두 **net-유의미성 미입증** — 통산 산수(-0.25/거래 잔존)를 뒤집을 크기라는 증거 없음. 결론은 "측정 착수 정당, 행동 레버 승격 부당"(양측 합의).
- 전 측정이 6월 단일국면+net_est 41% 커버리지 위 — 판정 시 명시 필수.

## 4. 실행 후보 (전부 매매 무변경, 운영자 지시 대기)
1. **H1 처리** — 죽은 config 배선 or 제거+문서화 (운영자 결정; 현 상태는 환상 안전장치라 방치가 최악)
2. **G2 측정** — stop_latency_overshoot_report를 profit-kind로 확장(1스텝), give의 시간성분 분해
3. **G1 측정** — 동시발화 노출 도구(진입시각 겹침×섹터맵→일별 동시보유 k vs 합산 net 꼬리 분위수)
