# 유령 실행(phantom execution) 설계 — 쉐도우를 실매매처럼 (2026-09-02 밤, 운영자 방향 확정)

**운영자 의도(정본)**: 쉐도우는 실매매처럼 운영해 **전략과 운영을 동시에** 검증한다. 실매수만 아닐 뿐
경로는 실전과 같아야 하고, 복귀는 "매수 경로만 열고 전략만 고르면" 되는 상태여야 한다.
근거·배경: `system_reanalysis_20260902.md`(8월 손실 주범 = 운영 결함), 메모리 `shadow-must-run-like-live-20260902`.

## 0. 원칙 (변경 불가)

1. **실전 코드 경로 통과** — 브리지 평가·게이트·수량·호가 → 유령 포지션 → 기존 출구 소유자(장중 틱 TP12/SL25/BE락4/D7)
   → 가상 청산. 새 정산 코드를 만들지 않는다(08-20 갈라짐 교훈).
2. **완전 격리** — 유령 포지션은 자금 회계·슬롯·일한도·리스크 한도·브로커 truth 어디에도 들어가지 않는다.
   실주문 복귀 시 가상 잔재가 실자금 한도를 먹는 사고 금지. integrity_check가 매일 격리를 검사한다.
3. **복귀 = env 두 줄 + 재시작 + arm 1개 선택.** 코드 변경 0. 유령 태그가 빠지고 브로커 체결이 붙는 것만 달라진다.
4. **판정 규율 불변** — 실시간 장부도 forward만·N 충족·paired LCB·max-stat(게이트 개정 1). 실매매처럼 운영한다고
   판정을 느슨하게 하지 않는다. 판정 표본을 실시간 장부로 바꾸는 것은 게이트 개정(운영자 승인) 사안.

## 2. ② 상세

- **생성**: `us_swing_order_bridge`가 `REHEARSAL_READY`를 찍는 지점에서 실주문 포지션과 같은 dict를 만들되
  `virtual=True`, `position_origin="phantom"`, `source_strategy="us_swing_5d"`, `exit_owner="us_swing_5d"`, 호가·수량·
  시각은 결정값 그대로. 저장은 `state/phantom_positions.json`(실주문 `live_open_positions.json`과 **파일 분리**).
- **보유·청산**: 출구 소유자가 실주문 포지션과 같은 루프에서 유령 포지션도 평가한다(같은 틱·같은 규칙).
  매도 판정 시 `_execute_sell` 대신 `_record_phantom_close(reason, price, ts)` → `[VIRTUAL] sleeve CLOSED` 로그·
  텔레그램(critical). 실주문 API 호출 0.
- **브로커 동기화**: `_sync_runtime_with_broker`의 stale 정리·quarantine·HALT 계산에서 `virtual=True`는 **제외**
  (없으면 "브로커에 없는 포지션"으로 삭제된다 — 가장 위험한 지점, e2e 필수).
- **원장**: `data/shadow/phantom_ledger.jsonl` — 진입/청산 이벤트(session_date, ticker, qty, 호가, 사유, 시각).
  07:20 체인 ⑩: 같은 (session_date, ticker)의 일봉 정산(`virtual_books.db` us_live_dvol)과 대조 →
  `data/shadow/phantom_vs_daily.jsonl`(진입가 차·청산 사유 차·net 차·보유일 차).
- **격리 검사(integrity_check 1행)**: 유령 포지션이 실주문 포지션 파일·슬롯 계산·리스크 한도·브로커 원장에
  존재하지 않을 것. 위반 시 FAIL.
- **텔레그램**: 진입·청산 둘 다 통보(기본값), `critical=True`.
- **첫 표본**: 09-02 SN(22:35 REHEARSAL, 2주 @171.27) — 원장에 이미 있으므로 재시작 직후 소급 생성해 오늘 밤부터
  출구 로직을 태운다.
- **테스트(e2e)**: REHEARSAL → 유령 생성 → 브로커 sync 후 생존 → TP 틱에서 가상 청산 → `_submit_*` 호출 0 →
  실주문 포지션 파일 미오염.

### 폐기·개선·편입 규칙 (승격 게이트 동결과 양립)
- **조기 폐기**: 사전등록 재앙 기준으로만 — 정산 30건에서 paired 알파 ≤ −2% / MaxDD > 20% / 운영 결함(격리 위반·
  정산 불일치 반복). `retired` 처리, 원장 보존, 판정 제외. 폐기는 다중검정을 줄이므로 언제든 안전.
- **개선**: 파라미터·규칙 변경 = **새 arm id(V2)**, forward 0에서 재시작. 표본 재사용 금지(=골대 이동).
- **신규 편입**: 별도 family로 등록(F1 숏·F2 페어·TSMOM·운영자 아이디어) → family 간 Holm에 자동 포함.
- **승격**: 게이트 정본 그대로. **폐기·개선·편입은 유동, 승격만 동결.**
- 위 규칙은 게이트 문서 **개정 2**로 사전등록한다(③ 착수 시).
