## A. 관측 계층 7종 — 검증 완료, 구현 확정 후보

설계 중 발견: **A1~A4는 데이터가 이미 쌓이고 있다.** shadow DB(`us_swing_shadow.db`)는
rank1~5 전 행을 정산하고(net_krw_pct), 차단된 rank1도 행이 남아 정산된다. 실행
원장에는 체결 시각이 이미 있다. 즉 **4건은 신규 기록이 아니라 판정 도구의 리포트
확장**이면 된다 — 비용이 예상보다 훨씬 작다.

## B. 비용·유휴 경로 — 감사 결과와 결정 요청

### B1. 죽은 경로 Claude 호출 ~180건/일 (운영자 결정 필요)

소비자 지도 (추적 완료):

```
single_symbol_judge 68건/일 → PathB 가격플랜 생성 → 플랜은 만들어지나
                              PATHB_KR/US_LIVE_ENABLED=false로 주문 차단
                              (08-05에도 KR 플랜 생성→WAITING→CANCELLED 확인)
analyst 3인방 84건/일       → 시장 모드 산출 → 소비자는 legacy 사이즈 조절
                              (legacy 매수 3중 차단) + micro_probe의 mode 라벨
tune ~30건/일               → momentum/continuation 등 매수 불가 전략 파라미터
brain.json 일일 갱신        → 소비자 전부 watch-only 경로
```

**전부 "관측 상태 유지 비용"이다.** PathB를 언젠가 재개할 계획이면 플랜 파이프라인
유지에 의미가 있고, 아니면 순수 낭비다. 선택지:

- (a) 현행 유지 — 옵셔널리티 비용으로 수용
- (b) judge·tune 빈도 축소 (예: 매일 → 주 1회 관측 유지)
- (c) PathB 재개 결정 전까지 정지 (재개 시 플래그로 복원)

권고: **(b)**. 관측 연속성은 남기고 비용은 ~80% 절감. 단 이건 지출 결정이라
운영자 몫이다.

**전후 차이:** 전 = 매일 ~180건 API 호출(대부분 소비자 없음) / 후 = 살아있는
소비자(매도 리뷰·리스크 게이트)만 유지, 관측은 저빈도.

### B2. 새벽 스크리너 0~4종목 — 오탐 정정, 종결

검증 결과 고장이 아니다. `collect_screener_pool`은 가격 CSV **증분 수집기**로
"이미 최신이면 스킵"하며 반환값이 신규 수집 수다. 0~4종목 = 대부분 최신이라는
정상 신호. **항목 종결.** (이 오탐이 C1의 근거가 됐다 — 내용물 크기를 봐야
오탐/진탐을 구분할 수 있다.)

### B3. 매도 리뷰 가치 판정 — 보류 (표본 부족)

측정 인프라(hold_advisor_exit_outcome: realized vs hold_fwd 카운터팩추얼)는
존재하나 24행에서 07-23 정지, 로그 백필 가능분도 12건뿐. legacy 매수 중단으로
Path A 매도 자체가 희귀해져 **판정 대상이 축소**됐다. 원장 writer 재가동 여부만
확인하고 판정은 표본이 생기면 한다.

## C. 감시 강화

### C1. 신선도 게이트에 내용물 차원 추가

B2 오탐 과정에서 확인된 사각: 게이트는 **파일 갱신 여부**만 보고 **내용의
유의미성**(행 수 정체, 빈 산출)은 못 본다. 원장류 파일에 "최근 N일 신규 행 수"
차원을 추가한다.

**전후 차이:** 전 = 파일이 매일 touch되면 내용이 비어도 🟢 / 후 = 원장이
증가를 멈추면 깃발.
