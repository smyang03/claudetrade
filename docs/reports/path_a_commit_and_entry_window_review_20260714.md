## 3. 처음 확인된 Path A 핵심 문제와 현재 상태

### 3.1 해결: 발견 지연 → 개장 분봉 부재 → ORP 신호 침묵

후보가 늦게 발견되면 OR 형성 구간의 분봉이 전략 입력에 없었다. 백필 함수가 원자료 분봉을 가지고도 비어 있는 캐시를 다시 참조해 OR 상태를 만들지 못하는 순환 의존이 있었다.

해결된 변경은 분봉으로 OR 상태를 직접 구성하고, 이를 Path A 전략 호출 전에 적용하는 것이다. 따라서 과거의 `orp_not_formed` 전체를 게이트 과잉이나 전략 임계값 문제로 해석하면 안 된다.

### 3.2 해결: 실패 관측 불능

KIS, 후보 신선도, 실적 캘린더, 판단 캐시 등에서 표준 핸들러가 없는 로거를 사용해 실패가 파일 로그에 남지 않는 경로가 있었다. 현재 해당 로거들은 프로젝트 표준 로거로 전환됐다.

### 3.3 해결: 운영 설정과 실제 실행 경로의 불일치

RR 임계와 target basis가 설정에 존재해도 일부 judge/adapter 경로까지 도달하지 않거나 하드코딩에 덮일 수 있던 문제를 정리했다. 기존 Path B 포지션을 새 임계로 소급 탈락시키는 회귀도 되돌렸다.

## 4. 미해결: `진입창 만료 57%`의 올바른 해석

### 4.1 원시 만료 행은 진입 실패 건수가 아니다

US live ORP 로그에서 명시적 `orp_entry_window_expired`는 3,779행이지만 고유 `세션+종목` 후보는 362개다.

| 지표 | 값 |
|---|---:|
| 만료 원시 probe 행 | 3,779 |
| 고유 만료 후보 | 362 |
| 후보당 평균 만료 기록 | 10.44회 |
| 5회 이상 기록된 후보 | 223개 |
| 한 후보의 최대 기록 횟수 | 57회 |

`trading_bot.py`의 ORP probe 기록은 전략 평가 때마다 실행된다. 따라서 장 후반에도 같은 후보가 계속 평가되면 만료 상태가 반복 기록된다. 원시 행 비율이 57%처럼 보이는 것은 이 반복 기록을 포함한 결과다.

### 4.2 창 안 `trade_ready`와 즉시 만료는 실제로 모순되지 않는다

US에서 ORP 추천이면서 창 안(장 시작 후 75분 이내)에 `trade_ready`가 된 행은 34건이다.

| 최초 평가 결과 | 건수 |
|---|---:|
| 2분 내 ORP 평가됨 | 22 |
| 2분 내 즉시 만료 | 0 |
| 첫 평가 `orp_not_formed` | 8 |
| 첫 평가 `orp_range_too_high` | 7 |
| 첫 평가 `orp_pullback_too_shallow` | 7 |
| 첫 평가 `orp_volume_low` | 3 |
| 이후 ORP 평가 자체가 없음 | 4 |

창 안에서 선정됐지만 첫 ORP 평가가 만료로 보인 3건은 실제 평가 시점이 선정 뒤 40~55분이었다. 따라서 `trade_ready` 뒤 +1분에 만료됐다는 사례가 아니다.

### 4.3 현재 확정할 수 있는 것과 없는 것

확정:

- 57% 원시 만료 비율은 Path A의 실제 최초 차단률이 아니다.
- 60분/70분 경계의 산술 버그는 없다. `entry_window_elapsed_min`은 OR 형성 이후의 경과시간이다.
- 창 안 후보의 첫 평가에서 즉시 만료보다 OR 형성·range·pullback·volume 조건이 더 자주 나온다.

미확정:

- 실제 신규 진입을 가장 많이 막는 최초 조건의 시장별 비율
- 창 안 후보 중 평가가 늦거나 없는 4건의 원인(스케줄, 후보 전달, 분봉 갱신, 루프 순서)
- 조건을 완화하거나 ORP 창을 연장했을 때의 net 성과

## 5. 별도 운영 상태: `rule_direct`와 Plan B 취소 confidence

`PLANB_CANCEL_CONFIDENCE_MIN=0.75`은 설정만 있고 죽은 값은 아니다. `trading_bot.py`에서 읽어 `runtime/action_routing.py`의 `PROBE_READY`/`BUY_READY` 라우팅 조건에 전달된다.

그러나 현재 `SELECTION_RULE_DIRECT_KR/US=true`는 의도적으로 Claude selection을 건너뛰고 `trade_ready=[]`, `WATCH` 중심의 후보를 만든다. 따라서 Plan B 취소 confidence를 요구하는 상위 액션이 거의 만들어지지 않아 운영상 발화하지 않는다. 이는 배선 버그가 아니라 현재의 선정 정책 효과다.

## 6. 다음 작업 순서

1. **ORP attribution 리포트를 후보 단위로 교체한다.**
   - 키: `session_date + ticker + selection_id` 또는 동등한 선택 이벤트 키
   - 각 후보에 대해 선정 시각, 첫 ORP 평가 시각, 첫 실패 사유, 첫 신호 시각만 기록
   - 반복 probe 행은 관측용 보조 지표로 분리

2. **`trade_ready → 첫 평가` 지연 원인을 분리한다.**
   - 0~2분, 2분 초과, 미평가로 버킷화
   - 미평가는 scheduler, 후보 전달, 분봉 수집, 루프 순서 중 하나로 원인을 태깅

3. **최초 실패 사유를 KR/US별 기준선으로 만든다.**
   - `not_formed`, `range`, `pullback`, `volume`, `expired`, `no_evaluation`을 상호배타적으로 집계
   - raw log 행 비율은 병목률로 사용하지 않는다

4. **그 결과가 나온 뒤에만 전략 파라미터를 검토한다.**
   - ORP entry window, range, pullback, volume 임계를 지금 완화하지 않는다
   - 각 완화안은 no-lookahead, 비용 반영, 시장별 분리, shadow/forward 검증을 전제로 한다

5. **운영 정책을 결정한다.**
   - `rule_direct` WATCH-only를 유지하면 Plan B 취소 confidence 게이트의 비발화는 정상으로 문서화한다
   - 실제 진입 재개가 목적이면 rule-direct 이후 단일 종목 judge에 `PROBE_READY`/`BUY_READY` 권한을 줄지 별도로 결정하고 검증한다
