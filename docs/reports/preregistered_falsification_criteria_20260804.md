# 사전 등록 — 급락 반등 레인 반증·확대 기준 (2026-08-04)

목적: "지금 당장 맞다고 못 한다"를 강하게 만드는 방법은 **틀렸을 때의 기준을 결과가 나오기 전에 고정**하는 것이다(사후 골대 이동 방지). 아래 기준은 forward 표본이 쌓이기 전에 등록됐다. 변경은 운영자 승인 + 변경 사유 기록으로만.

## US us_swing micro (일1건×30만, 슬롯3)

| 시점 | 판정 | 기준 |
|---|---|---|
| forward 30건 | **확대 허가** | net 합 > 0 AND 평균 알파(동일 구간 IWM 대비) > 0 → 일3건 재론 |
| forward 30건 | **정체** | net > 0 이지만 알파 ≤ 0 → "지수 매수 대비 무가치" — 확대 불가, 선별 개선 과제로 전환 |
| forward 30건 | **경고** | net ≤ 0 → 일1건 유지, 원인 분해(국면/슬리피지/선별) 후 운영자 보고 |
| forward 60건 | **반증** | net ≤ 0 지속 → 운영자에게 레인 중단·재설계 제안 (결정은 운영자) |
| 상시 | **즉시 점검** | 단일 거래 슬리피지(체결가 vs 신호시점 시세) > 1% 반복 3회 → 사이징·유동성 하한 재검토 |

- 알파 정의: 각 거래의 net − (진입~청산 동일 구간의 IWM 수익률). 산출: `tools/kr_fallen_gate_report.py` 계열 리포트.
- 표본 카운트는 day_losers 전용 전환(2026-08-03) 이후만. 구소스 혼합 신호·고정보유 회계(−239%p 계열)로 판정 금지.

### 코호트 정의 개정 (2026-08-07 — 정산 0건 상태의 사전 수정, 골대 이동 아님)

실측 사고: 절대 허들(확률 0.55·예상 net 0.25%)이 실주문 핸드오프에만 있고 shadow 계약에 없어,
live가 차단한 ULS(0.418)·LCID(0.386)는 코호트에 들어가고 live가 체결한 FRMI(08-03, 38@5.5225)는
구계약 slot 이월(`slot_occupied_pending:2026-07-29`)로 빠졌다. 정정 규칙을 정산 발생 전에 고정한다:

1. **execution 코호트 = 실주문과 동일 계약 전체**(예산·슬롯·소스·TP/SL·**절대 허들 포함**)로 선정된 건만.
   허들 차단 건은 counterfactual 관측(판정 리포트 [A2])이며 판정 표본이 아니다.
2. **실주문 전건 포함이 정본.** 실제 제출·체결된 건은 코호트에 소급 포함한다(FRMI 08-03 포함).
   결과를 보고 넣는 것 아니냐는 시비 방지: 포함 기준은 "실주문 여부"라는 사전 규칙이지 성과가 아니며,
   반대로 실주문인데 shadow가 빠뜨린 건을 제외하는 것이야말로 표본 편향이다. 정산 수치의 정본은
   실체결 원장(`execution_shortfall_ledger`)이고 shadow 정산은 근사 검증치다.
3. **슬롯은 현재 contract_id 행만 점유한다.** 구계약 shadow 행의 이월 점유 금지. 브로커 실보유
   슬롯은 실주문 경로(order bridge)가 별도로 센다.
4. 허들이 계약 지문(contract_id)에 포함되므로 이 개정으로 id가 재계산된다. 08-03~06 행은
   새 id 기준으로 재판정(re-annotate)해 정정한다 — 정산 0건 상태라 성과를 보고 고르는 여지가 없다.

### 코호트 정의 보충 — 주문금액 변경 시 (2026-08-16 기록, 정산 규약 불변)

**사실**: 2026-08-14 운영자 지시로 US swing 주문금액을 30만→50만으로 인상했고, 예산이
계약 지문 입력이라 `contract_id`가 `367576a1b8bf7802` → `afc07db83b6ad8a6`로 바뀌었다
(08-14 DIOD부터 신 지문). 지문 이력: 1436a5b1(08-03~07, 허들 있음) → 367576a1(08-08~13,
허들 폐지) → afc07db8(08-14~, 50만).

**규약**: 30건 판정 카운트는 **코호트 정의 2항(실주문 전건 포함) 그대로 이어간다.**
판정 기준이 net%(비율)이므로 주문금액은 판정 유효성을 바꾸지 않는다 — 건당 절대손익만
비례 확대된다(SL −25% 시 −7.5만 → −12.5만). 판정 리포트는 지문별 코호트를 분해 병기해
금액 변경 전후를 사후 확인 가능하게 유지한다. **금액 변경을 이유로 카운트를 리셋하지
않는다** — 리셋은 계약의 *행동*(진입·청산 규칙, 선정 조건)이 바뀔 때만 한다.

### 리스크 한도 개정 — 100만원 (2026-08-17 운영자 결정, 사전등록 갱신)

**사실**: US swing 주문금액을 50만→**100만**으로 인상했다(`US_SWING_ORDER_MAX_KRW`,
.env.live·start-config 동시 변경). KR fallen은 `KR_FALLEN_ORDER_MAX_KRW` 30만 **불변**
(별도 키 — 이번 변경의 영향 없음). 지문 이력에 4차 변경이 추가된다.

**이 개정이 무효화하는 기존 한도**: `design_kr_lane_v2`(§3 Phase 3)와
`design_tp_capture_lane`(§3 쟁점3)이 못박은 **"동시 SL 최악 ≤ −30만"** 조항. 08-14 50만
인상 시점에 이미 −37.5만으로 초과 상태였고 갱신 기록이 없었다(2026-08-17 발견).

**새 한도(이 문서가 정본)**:

| 항목 | 값 |
|---|---|
| 건당 주문(US swing) | 100만원 |
| 동시 보유 슬롯 | 3 (불변) |
| 최대 동시 노출 | 300만원 — **US 주문가능액 기준 90.1%** (2026-08-17 실측 $2,359.47 ≈ 333만원, 여유 33만) |
| **동시 SL 최악(−25%)** | **−75만원** = KIS 총자산 약 15.4% |
| 역사적 최악(−27.2%) 기준 | 약 −81.5만원 |

**판정 규약**: 위 30건 카운트 규약과 동일하게 **리셋하지 않는다**(net% 기준·행동 불변).
지문별 분해 병기는 그대로 유지한다.

**자본 제약(2026-08-17 실측 정정)**: KR 잔고 96만은 US 주문에 쓸 수 없다. **US 단독
가용은 약 333만원**이므로 3슬롯을 다 채우면 소요율 **90%**(전체 현금 429만 기준 70%가
아니다). 여유가 33만이라 FX 변동·미체결 예약이 겹치면 **3번째 진입이 affordability로
조용히 막힐 수 있다** — 그때는 슬롯이 아니라 현금이 병목이므로 로그에서 사유를 구분해
읽어야 한다.

**인상의 실제 이점(고지 시 누락, 08-17 실측 보완)**: 고가주가 예산 미달로 표본에서
빠지는 사고를 줄인다. 08-07 rank1 AXON($522.46)은 **50만 예산에서 0주**라 애초에 살 수
없었고, 100만이면 1주다. 과거 `micro_budget_cannot_buy_one_share` 3건(WEX·AXTI·SNDK)이
같은 계열이다(단 SNDK $1,278급은 100만으로도 불가).

**운영자에게 고지된 반대 근거(기록 보존)**: ① 금액 인상은 판정 속도에 기여하지 않는다
(표본은 건수로만 는다) ② 정산 표본 n=3에서 베팅 2배 ③ TP12/SL25는 음의 비대칭(손익분기
승률 67.6%) ④ 현금 70%가 묶여 KR 게이트 통과 시 자본 부족. 운영자가 이를 확인하고
진행을 결정했다. **정상 낙폭 범위(아래 §)도 같은 배율로 재해석한다** — 건당 30만 기준
−30만 낙폭은 100만 기준 **−100만**에 대응한다(비율 불변, 절대액만 비례).

### 리스크 한도 재개정 — 슬롯 5 × 76만 (2026-08-20 운영자 결정, B안)

**발견(이 개정의 근거)**: `D5 보유 × 일1건`이면 정상상태 동시보유는 **5개**다. 슬롯 3은
진입률을 `3/5 = 0.6건/일`로 **강제로 깎는다**. 실측이 이론과 일치한다 — 08-03~08-19
13거래일 동안 US 진입 7건 = **0.54건/일**. 즉 US는 후보 부족이 아니라 **슬롯이 병목**이었다.

**변경**: 주문상한 100만→**76만**(`US_SWING_ORDER_MAX_KRW`, 두 소스 동시), 슬롯 3→**5**
(코드 상수 2곳: `us_swing_execution_contract.OPERATOR_TRIAL_MAX_OPEN_SLOTS`,
`us_swing_order_bridge` authority dict). **일1건은 불변.** KR fallen 30만 불변.

| 항목 | 이전(08-17) | **신규(08-20)** |
|---|---|---|
| 건당 주문(US swing) | 100만원 | **76만원** |
| 동시 보유 슬롯 | 3 | **5** |
| 최대 동시 노출 | 300만원 | **380만원** (US 자본 383만의 99%) |

| 30건 도달 추정 | 10월 중순 | **9월 중순** |

**근거**: 자본 383만 고정에서 `3×100만`(투입 300만)보다 `5×76만`(투입 380만)이
**투입 +27%, 표본 +85%**로 우월하다. TP/SL이 **퍼센트 계약**이라 포지션 크기를 줄여도
건당 수익률은 불변 — 크기 축소의 대가가 없다. 검증 국면(8/30)의 목표는 수익 극대화가
아니라 **게이트 도달**이다.

**고지된 반대 근거(기록 보존)**: ① 08-17 인상(50→100만)을 사흘 만에 부분 되돌린다
② 미검증 계약(8/30)에 투입을 300만→380만으로 늘린다 ③ 최악 동시 SL이 총자산의
15.4%→18.4%가 된다 ④ 76만으로는 고가주(AXON $522급 1주 = 약 74만)가 아슬아슬하고
$700 이상은 다시 `micro_budget_cannot_buy_one_share`가 된다(08-17 인상의 이점 일부 반납).
⑤ US 현금 여유가 사실상 0이 되어 FX 변동 시 5번째 슬롯이 조용히 막힐 수 있다.
운영자가 이를 확인하고 진행을 결정했다.

**KR 동반 결정**: `KR_FALLEN_PHASE3_CAPACITY_ENABLED=true`(슬롯 1→3, 사다리 k=1→1건/
k=2~9→2건/k=10+→3건). 단 **KR은 슬롯이 병목이 아니라 후보 공급이 병목**임이 실측됐다 —
원장 40세션 중 후보 0건 8회·1건 17회(합 62.5%)로 과반에서 Phase 3가 아무것도 바꾸지
않는다. 8월은 13세션 중 다발일이 08-03 하루뿐. **가속 기대는 하지 않되 비용도 없어
켜둔다**(다발일에만 자동 발동). 최악 동시 SL은 3×30만×25% = **−22.5만**.
**US 95만 + KR 22.5만 = 총 −117.5만(총자산 약 22.8%)이 새 전체 한도다.**
