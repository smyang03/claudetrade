# 공격(수익 창출) 레버 3축 탐색 — 분봉 replay (2026-07-04)

운영자: "FX·방어 빼고, 공격(수익)에서 DB상 놓친 걸 다양하게 3명 토론+검증." 3에이전트가 공격면(상방 더 잡기)을 각자 분봉 양방향 replay + MFE 재계산으로 파고, **공정 상대우위 검증**(baseline 대비 Δ가 outlier·OOS 견디나 — trail-vs-cap 교훈)으로 거짓양성/거짓기각 둘 다 방지. read-only.

## ★결론: 공격면에 robust 수익 레버 없음 — 원인은 구조적 "상방=하방 결합"

3축 전부 같은 벽: **fat-tail 러너의 상방(MFE)은 실재하고 약하게 식별되나, 동일 셋업의 하방(MAE)이 비례해 net으로 전환 안 됨.** 러너와 급락주가 진입시점에 구별 불가.

| 공격 축 | 후보 | 판정 |
|---|---|---|
| **①MFE 상방원천** | reward_pct 4-8 & gap↓ = fat-tail 33% 식별(6월 OOS 견딤) | **net 역전**: 최고MFE셀 실제 net −1.06(최악), 최저MFE셀 +0.40(최고). 高MFE=高MAE→−2%손절 먼저. **사이즈 실을 레버 아님** |
| **②조기청산 상방 leak** | LADDER/STOP capture 28~40%(peak 남김) | **실행가능 늦게팔기 전부 중앙 음수.** 익일 +6.22% 고점=hindsight 신기루(give-back+오버나잇갭 회수). 재량출구는 잘 판 것. **leak 아님** |
| **③사이징·불타기·재진입** | 터진 러너 증량 | **전부 죽음**: 꼭지 근처 증량=되밀림 증폭(exit가 peak −1.6~2.8%p). 재진입=국소꼭지 매수. 사이즈틸트=신호 무변별. **고정 500k 유지** |

## 유일한 실측 공격 edge = trail>cap (이미 배포)
"승자를 +4에서 안 자르고 태우기(trail)"는 cap(+4 고정목표) 대비 **견고한 상대우위**(양월 모두, outlier 빼고도: 6월 trail −21 vs cap −102, Δ+81). = 진짜 capture 공격. **단 절대 흑자는 fat-tail 출현 의존**(러너 없으면 본전, 있으면 잡음). 이미 `US_LADDER_AB_MODE=enforce`로 배포됨 → 시스템이 이미 하는 유일한 공격.

## 구조적 진실 (공격면 exhaustive 후)
1. **gross edge 자체가 얇음**: US gross +0.19/거래, KR +0.44. 비용 0 이어도 얇은 양(+). 이 얇은 edge를 두껍게 할 DB 레버가 selection·capture·sizing 어디에도 없음(전부 탐색 완료).
2. **상방=하방 결합**: 큰 러너 셋업은 큰 드로다운 동반 → 상방만 harvest 불가. 이게 capture·sizing·carry 공격이 다 죽는 공통 死因.
3. **수익=fat-tail 출현(예측불가)을 trail이 잡는 것**. 빈도·국면 luck 의존. 시스템은 이미 그걸 함(trail 배포).

## 정직한 함의 (DB 재단으로는 끝)
공격면 DB는 exhaustive하게 채굴됨 — **놓친 레버 없음.** 남은 건 DB 재단이 아니라 **구조 변경**(운영자 전략 결정): ①다른 유니버스(상방=하방 결합이 덜한 저변동 종목?) ②비용측 churn 축소(적게·크게·오래 = FX 아닌 시스템측, 단 gross 얇아 상한 낮음) ③fat-tail 빈도(우호국면 노출 — but 초록tape도 본전, 매수확대 −EV로 기각됨). 흑자 천장은 구조적: 얇은 gross − 비용 = 본전 근방.

## 결론
운영자 지시대로 공격면을 다각도(상방원천·조기청산·증량) exhaustive 탐색. **DB상 놓친 공격 레버 없음.** 이미 배포된 trail(승자 태우기)이 유일한 실측 공격이고, 나머지는 상방=하방 결합으로 전멸. 흑자는 DB 재단이 아니라 구조 변경(유니버스/비용/빈도)에서만 가능하며, 그건 운영자 전략 결정 영역이다.
