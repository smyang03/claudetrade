# 검증형 트레이딩 봇 — 1차 안전 보강 및 연구 계약 정의

## 구현 범위

목표는 수익을 보장하는 새 전략 추가가 아니라, 검증하지 않은 결과가 실주문 권한으로 바뀌는 경로 차단이다. 실매수 스위치, 활성 전략 ID, 운영 프로세스는 변경하지 않았다. 커밋·푸시·재시작도 하지 않았다. 아래 수정은 다음 해당 코드 실행부터 적용되며 이미 실행 중인 프로세스에 자동 반영됐다고 주장하지 않는다.

- `forward_gate_watch`: 완결된 진입일 코호트만 집계한다. 같은 코호트에 OPEN/비정상 수익이 있으면 먼저 청산된 승자만 세지 않는다. 비정상 CLOSED 수익은 DATA_INVALID. 최소 30진입세션을 추가하고 표본 표준편차를 사용하며 반기별 부호와 상위2세션 제외 성과를 확인한다. 최고 판정은 REVIEW_REQUIRED, 권한은 RESEARCH_ONLY다.
- 30세션은 최소 연구 검토 문턱이지 독립 표본 30개라는 뜻이 아니다. 보유기간 중첩·시장 공통 충격·다중 전략 탐색·반복 평가가 남으므로 t≥2.5를 통계적 확증으로 쓰지 않는다. 반기 검사는 실제 서로 다른 달력 반기 2개 이상을 요구하며, 한 반기 자료를 임의로 둘로 나누지 않는다.
- `canary_policy`: 누락/미승인 정책, 손실 원장 손상, 미등록 ID를 차단한다. 과거 CANDIDATE_STRONG 상태 파일도 신규 주문을 승인하지 않는다. 신규 캐너리는 실행 검증과 2단계 어댑터가 없으므로 전부 execution_validation_pending이다. 기존 us_swing_5d/kr_fallen_5d의 별도 주문 스위치와 공유 실현손실 검사는 유지한다.
- 기존 전략의 공유 손실 검사에서는 원장이 아직 없는 상태를 기존대로 0으로 취급한다. 이것을 미실현/대기 주문까지 포함한 완전한 위험 검사라고 부르지 않는다. 신규 캐너리는 해당 위험 증거가 없으므로 계속 차단된다.
- `canary_materializer`: 전량/상위5개 전략을 임의의 K1로 바꾸지 않는다. dvol_desc·daily_cap=1인 연구 계약만 선별 리허설을 허용한다. 원본 연구 계약 지문을 남기지만 이 지문만으로 주문 수량·현금·체결까지 일치했다고 주장하지 않는다. canary_allowed는 항상 false다.
- 완결 일봉을 먼저 고른 뒤 최신 날짜를 선정한다. 시장별 거래소 개장 시각으로 다음 진입일을 정한다. 미국장 개장 전 21:05 KST는 당일 미국 세션이다. 달력 조회 불가 시 평일 추정으로 대체하지 않고 신호를 차단한다.
- 만기 가격 참조는 진입일 포함 H번째 완결 봉을 사용한다. 이는 TP/SL/BE를 재현한 성과가 아니며 MATURITY_PRICE_REFERENCE_NOT_STRATEGY_PNL로 명시한다. 기존 SETTLED 원장은 덮어쓰지 않아 과거 버전은 그대로 남는다. 이전 리허설을 새 실행 검증 표본으로 합치면 안 된다.

## 연구 축 3개: 공통 정의를 먼저 고정

아래는 개발 명세이며 수익성이 검증된 계약이나 실행 가능한 신규 전략 등록이 아니다. 아직 선택하지 않은 종목·임계값을 임의로 승인하지 않는다. 미정 항목을 채우고 버전/지문/평가일을 확정한 시점부터 새 forward 표본을 시작한다. 기존 표본은 탐색 자료로만 사용한다.

|---|---|---|
| 비레버리지 ETF 패닉 오버나이트 | 15:19까지 실제 수신한 정보만 신호에 사용. 종가 동시호가의 실제 주문 가능 가격/미체결을 기록하고 다음 실제 거래일 시가 청산을 비교. 마감 지수를 보고 같은 종가에 샀다고 가정하지 않음 | 원 연구 코드·가격 스냅샷 복원, ETF/하락 임계값/비용·주문 마감 확정, 동일 ETF 무조건 진입 비교군 정의 |

## 다음 개발 순서

1. 하나의 후보에 대해 정수주·현금·동시보유·미체결·호가 지연·실제 출구를 반영한 실행 쉐도우 원장을 만든다. K1 신호와 만기 종가 참조를 포트폴리오 성적으로 대체 계산하지 않는다.
2. 동일 계약의 일봉 추정과 실행 쉐도우를 사건별 대조한다. 기저 대비 비용 후 추가효과, 상위 사건 의존, 낙폭, 거래 불가율을 함께 보고한다.
3. 평가일·전체 탐색 후보 수·중첩 보유기간·검정 방법을 고정한다. 독립된 최종 평가에서 살아남은 경우에만 승인 증거의 유효기간/계약 지문을 설계하고 주문 어댑터를 구현한다.
4. 미실현손익·수수료·대기 주문·실제 활성 캐너리 수를 포함한 위험 검사를 만든다. 그 이후에도 실매수 재개는 별도 승인이다.

현재 완료는 안전 보강과 계약 명세까지다. 실행 포트폴리오 검증, 세 축의 신규 수집기, 자동 학습 모델, 실주문 어댑터는 이번에 구현하지 않았다. 전략을 늘리는 것보다 한 계약의 비용 후 초과수익을 재현하는 것이 다음 목표다.

## 검증 결과

- 신규 안전 테스트 34건 포함 관련 테스트 95건 통과: forward/canary, virtual_books 가격 대기, KR fallen 주문 브리지, US swing 주문 브리지 E2E, profit_strategy 주문 브리지. 실제 주문을 실행한 테스트는 아니다.
- Python 컴파일, 정책 JSON 구문, 수정 대상 diff 공백 검사 통과.
- 현재 virtual_books.db를 읽기 전용으로 재집계: 신규 19개 arm은 모두 완결 forward 0건. 17개 ACCUMULATING(0/30), 2개 ACCUMULATING(0/20). 기존 탐색/과거 재생 거래 수와 혼동하지 않는다. 패닉 별도 원장은 이 19개 집계에 포함하지 않았다.
- 운영 상태 파일·대시보드·리허설 원장은 재생성하지 않았다. 새 판정/표시는 다음 스크립트 실행 시 생성된다. 실행 중인 봇의 모듈은 재시작 전 구버전일 수 있다.
