# 토론 판정 — 시스템 근본 구조 전환 (2026-07-05)

## 명제
"Claude(LLM)의 예측·종목선정 능력에 의존하는 현 능동매매 구조는 edge가 없으므로, 예측 의존을 버리고 근본 구조를 전환해야 한다."

- 데이터: `v2_path_runs` CLOSED n=272(net n=263), 2026-04~07, net=`pnl_pct_net_after_fx_est`(백필 커버리지 95%). read-only.

## 판정: **조건부 찬성 (예측 축 전환 O / 시스템 폐기·재구축 X)**

예측 selection 의존을 버리는 것은 찬성(양측 합의). 그러나 시스템을 갈아엎어 다른 구조로 "재구축"하는 것은 반대 — rule 기반 관리 엔진(출구·손절·방어)이 robust하게 살아있고, 대안이 더 낫다는 in-repo 증거가 없다. **실질 처방은 PRO/CON 수렴점: 예측 selection 리소스 중단 + rule 방어 강화 + 회전 축소.**

## 사회자 검증 — 결정타
**"나쁜 국면 진입(red-tape 빨간tape)을 방어로 다 막으면 흑자로 가나?"**
- 빨간tape n=53, 각 net −1.17(도구 기준). 전부 회피 시 US net −67.6 → 약 **−5.6 (본전 근처, 흑자 아님)**.
- → **방어의 천장 = 본전.** CON의 "관리 강화로 개선"은 맞지만 개선의 도착지는 흑자가 아니라 본전. PRO의 "edge<비용"도 맞지만 전환이 흑자를 보장하지도 않음.

## 불일치 → 프레이밍 차이 (실질 처방은 동일)
- PRO "근본 전환(저회전·노출관리·방어)" vs CON "현 구조 유지+관리 강화(red-tape·zone-fill)".
- 두 방향이 **같은 곳**을 가리킨다: 예측 selection에서 멀어지고 rule 기반 방어/노출관리로 무게중심 이동. 명칭만 다름.

## 미결 (데이터로 판정 불가 = 운영자 영역)
- **"흑자를 원하면?"** — 현 구조 내 미세조정(방어 강화)의 천장은 본전이다. 흑자 엔진은 이 시스템 안에 없다(fat-tail 운 + 우호 국면에만 +). 흑자를 목표로 한다면 **시스템 밖**(다른 자산/전략 철학/규모 축소·중단)이고, 이는 in-repo 데이터로 판정 불가 — 순수 운영자 결정.
- 대안 구조(추세추종 등)가 현 구조보다 낫다는 저장소 증거: **없음**(PRO도 주장 안 함).

## 실행 함의 (데이터 지지 방향, 승인은 운영자)
1. **예측 selection에 개발 리소스 투입 중단** (무알파 확정, 양측 합의).
2. **rule 방어 강화** — red-tape enforce(배포됨)·zone-fill shadow(배선됨)의 forward 검증. 흑자 아닌 손실축소·본전화.
3. **회전 축소** — 저빈도가 비용 관점에서 유일하게 부호무관 net 개선.
4. **흑자 목표 시 구조 밖 결정** — 운영자 몫. 데이터는 "현 구조 미세조정으로 흑자 전환 불가"까지만 말한다.

## 정직 flag
