# 토론 판정 — 결정시점 정보(no-lookahead)로 패자 후보를 프롬프트로 거를 수 있나 (2026-07-01)

12관점(PRO/CON ×2, US/KR) + 사회자 검증(OOS + API). read-only, 메모리 무시 원점 재검증.

명제: "결정시점 정보(미래값·forward 금지)만으로 프롬프트 개선하면 '샀다면 손실' 후보를 걸러낼 수 있다(lookahead-free 분리신호 실재)."

## 판정: **반대(기각)** — 강한 분리신호 없음, 약한 시장조건부 틸트 + 좁은 abs() 결함만

## 사회자 직접 검증 (판정 가른 것)

**① OOS 검증 (6월, 1관측/종목-일, forward_1d 라벨):**
- US: chg<0(빨강) 패자율 57% vs 초록 49% (fwd -0.73 vs -0.06) = 빨강 8pp 나쁨, OOS 생존(약함)
- KR: 빨강 57% vs 초록 65% (fwd -1.07 vs -2.01) = **부호 역전**(KR은 초록=추격이 나쁨)
- → 방향 신호 실재하나 시장마다 정반대(US 모멘텀/KR 평균회귀), 약함(8pp on 49% base), gross-forward.

**② abs(change_pct) 결함 (코드 확인):** candidate_pool_runtime.py `change_pct = abs(...)` — 부호 버림(과열 페널티가 -8%를 +8%처럼). PRO-A 구조지적 사실.

**③ API 검증 (sonnet-4-6, 결정시점 데이터만):** 부호맹목(A) vs 부호인식(B) — CRCL(-16.5% 패자) 둘 다 AVOID(A도 |16.5|>12 임계로 이미 거름), BE/KLAC(초록 승자) 둘 다 BUY_READY. **A=B 동일** → abs() 결함은 극단빨강엔 무관, -1~-12% 중간빨강서만 실효(엣지 그 약한 8pp).

## 결론
**프롬프트로 패자를 신뢰성 있게 거를 수 없다.** 결정시점에 패자와 승자가 구별 안 됨(pooled AUC ≈0.5). selection 무알파가 no-lookahead 원점 재검증서 재확인됨(메모리 무시하고도 동일 결론). 부스러기 2개: ①US-only "중간빨강 회피" 8pp(abs() 고치면 닿으나 좁고 약함, gross) ②KR 추격회피(시스템이 이미 눌림선별로 처리). 레버는 selection 프롬프트가 아님. enforce 주장 불가(다국면·실종가·net 미검증).
