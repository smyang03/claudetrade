# 토론 판정: 급등주 스캘프(빠른 진입·빠른 익절)는 net 이득이 되는가

- 일자: 2026-06-30
- 형식: 12관점 찬반토론(PRO 2 / CON 2 입론 + 사회자 직접 검증), read-only
- 명제: "급등주를 빠른 진입·빠른 익절(스캘프, 보유 수십분~수시간)하면 KR 왕복비용(≈0.3~0.5%) 차감 후 net 이득이 된다"
- 전제: 메모리 결론(예측 무알파·추격 좌측꼬리) 무시하고 forward_3d(보유) 아닌 분/시간 스캘프 관점으로 신규 검증

## 판정: 명제 **반대(기각)** — 단, "빠른 청산" 하위레버는 별개로 생존

"**빨리 들어가**"(급등 진입 스캘프) = net 음수로 기각.
"**빨리 팔고 나오기**"(보유 포지션 빠른 익절) = 진짜 레버지만, 이건 진입 스캘프가 아니라 **기존 보유 종목의 출구 타이밍** 문제 — 기존에 식별된 capture leak 레버와 동일.

## 사회자 직접 검증 (판정 가른 단일 측정)

데이터 품질 함정 먼저 규명: `ticker_selection_log` change_pct 시계열은 `-99`(장전 무데이터) + `kr_wait60_reeval` 소스의 과거값 재생(예: 475430 14:09:36 rescreen=-0.75 직후 14:09:47 reeval=2.85로 옛값 복제)으로 오염. CON-A의 fade 65%·PRO-A의 추가runup 0.00은 이 오염 시계열로 계산됨.

→ fresh 소스(rescreen/partial)만, change_pct>-90으로 **clean 재측정** (KR, n=409 종목-일, ≥3스냅·감지≥5%):

| 측정 | 결과 |
|---|---|
| 감지(+5%) 후 추가 헤드룸 (max−detect) | **중앙값 0.00pp**, mean -0.17, p75 +1.19 |
| 추가 헤드룸 >0.5% 비율 | **37.2%** (152/409) |
| 감지 후 종가 순변화 (last−detect) | 중앙값 **-1.74pp**, mean -3.74 |
| fade(종가 -0.5% 이하) 비율 | **62.3%** (255/409) |

**결론: 스크리너가 +5%를 감지하는 시점엔 상방이 이미 소진(추가 헤드룸 중앙값 0).** PRO가 든 +9.5% 봉우리(max_runup_3d)는 (a)감지 전 같은날 이미 실현됐거나 (b)3일에 걸친 멀티데이 상방 — **스캘프 창(당일 감지 이후)에선 접근 불가**. 진입 시점부터 보면 중앙값 0 상방 / -1.74% 드리프트 / 62% fade이고, 여기서 KR 비용 0.5%와 실행 마찰을 빼면 net 음수.

## 핵심 논거 요약

- **PRO 최강**: 봉우리 헤드룸 실재(+9.5%) + capture leak(MFE +3% 찍고 net 0 회수) → 빠른 익절 여지. **그러나** clean 검증서 그 헤드룸이 진입(감지) 시점엔 0으로 소진 = 진입 스캘프엔 부적용. 살아남은 건 출구 타이밍뿐.
- **CON 최강**: 감지 후 추가 상방 중앙 0·fade 62% + 비용 floor 0.5~0.8% + 실행구조가 추격 거절. 진입 스캘프 net 음수가 산술·구조·실측 3중 수렴.

## 측정해야 결판날 것(진입 스캘프 미결 잔여)

진입 스캘프를 끝까지 검증하려면: **`micro_probe_log`로 KR 한정 소표본 shadow A/B** — 감지 즉시 시장가형 진입 + `exit_horizon_min` 고정(예 15/30/60분) 실현 net을, 비용·슬리피지 실측 포함으로 ≥20건 누적. 현재는 0행이라 "추론상 음수"이지 "실측 음수"가 아님. (단 비용·실행 차단 논거가 이미 강해 우선순위는 낮음.)

## 운영자 판단용 한 줄

"빨리 들어가"는 기각(상방은 감지 전에 끝남 + 비용·실행 벽), "빨리 팔고 나오기"는 진짜지만 그건 급등주 진입이 아니라 **이미 들고 있는 종목의 출구 타이밍(capture leak)** — 새 발견이 아니라 기존 레버 재확인.
