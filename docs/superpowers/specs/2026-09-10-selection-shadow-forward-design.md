# 독립 선택 비교 SHADOW — 수집·가상 체결·대시보드 연결 설계

작성일: 2026-09-10. 상태: 승인 범위 구현·운영 연결 확인 완료, 첫 유효 가상 체결 대기. KR 입력 부족·US CACHE_ONLY 제한 및 전체 테스트의 기존 실패 3건은 [운영 반영 보고서](../../reports/selection_shadow_forward_activation_20260910.md)에 기록했다.

## 목적과 권한

운영자가 승인한 범위는 기존 K1, 무작위 K1, 최대 3종목 분산을 같은 자본 조건으로 신규 관측하고, 가상 매수·보유·매도와 입력 결손을 `/virtual`에서 확인하는 것이다.
수익을 보장하거나 전략의 실매매 승격을 자동화하지 않는다. 실주문 스위치, 계좌 잔고, 기존 포지션 및 기존 유령 원장은 변경하지 않는다.
기존 가격/IBS 필터는 장기 검증에 실패했으므로 신규 매수 전략에 포함하지 않는다. 악재 필터도 이번 연결 작업에는 포함하지 않는다.

## 확인한 기존 구조와 선택

- `tools/selection_account_compare.py`: 과거 캐시를 이용하는 읽기 전용 계좌 비교. 신규 관측의 체결 엔진으로 사용하지 않는다.
- `tools/observe_arm_picks_realtime.py`: US 결정 시점의 전략 선택을 원장에 기록한다. KR 탐색 풀은 대상이 아니다.
- `runtime/phantom_book.py`: US 유령 진입·출구를 처리하며 같은 세션/종목/청산 계약의 포지션을 병합한다.
- `trading_bot.py`: 기존 유령 진입·평가 호출 지점이 있다. 이 지점의 시세·시장 시계 연결 패턴을 참고한다.
- `tools/discovery_pools.py`: KR 급락 풀의 신호일 지표와 조건을 제공한다. 과거 전체 재생의 세션 구성은 신규 수집에 그대로 사용하지 않는다.
- `tools/shadow_observers_hidden.vbs`: 일일 관측·가상 장부·평가 체인이다. 장 시작 후 이 체인이 끝나기를 기다렸다가 과거 시가에 진입하는 방식은 금지한다.
- `dashboard/dashboard_server.py`: `/virtual`, 기존 가상 계좌·유령 API와 연구 패널이 있다.

대안은 기존 유령 포지션에 새 arm을 붙이거나, 완전히 별도 봇을 만드는 것이다. 전자는 독립 자본이 섞이고 후자는 운영 프로세스가 중복된다.
채택안은 **기존 실행 흐름·시세 어댑터를 활용하되, 별도 비교 원장과 계좌 상태를 가진 SHADOW 모듈**이다.

## 데이터 흐름과 모듈 경계

`시장별 수집 → 입력 스냅샷 고정 → 전략별 선택 고정 → 판단 이후 시세 관측 → 가상 체결 → 보유/청산 기록 → 읽기 전용 대시보드`

예정 경계:

- `runtime/selection_shadow_book.py`: 독립 계좌·선택·체결 상태 전이와 원장 트랜잭션. 브로커 주문 객체를 받지 않는다.
- `tools/selection_shadow_runner.py`: 시장별 입력 수집·갱신·상태 조회 명령. 기존 자료는 읽기 전용으로 접근한다.
- 봇 어댑터: 시장/세션 시계와 읽기 전용 시세만 전달한다. 호출 시간 상한과 주기를 두어 실운영 루프를 지연시키지 않는다.
- 대시보드: `/api/selection_shadow` 조회 API와 `/virtual`의 독립 비교 패널. 화면 조회가 수집이나 체결을 발생시키지 않는다.

순수 계좌 엔진과 I/O 어댑터를 나눈다. 외부 시세 실패는 명시적인 상태로 기록하며, 봇의 주문·위험 관리 오류로 전파하지 않는다.

## 모집단과 입력 고정

시장마다 독립적인 v1 실험을 시작한다. KR/US 수익률을 섞어 전체 수익률을 만들지 않는다.

- US: 현행 eligible AND in_pool 후보를 읽고, 직전 완결 세션의 거래대금 100M 이상 500M 미만 및 MAX21≥8 조건을 적용한다. 필수 특징 누락은 제외 사유로 남긴다.
- KR: 관측 시점의 가격 파일 목록을 모집단으로 고정하고, 직전 완결 세션 등락률≤−3%, 거래대금≥20억원의 기존 `xkr_fallen3` 조건을 사용한다. 과거 거래 DB에서 다음날 종목을 가져오지 않는다.
- KR 파일 목록의 종목 유형 확인 결과를 기록한다. ETF가 섞인 기존 모집단을 조용히 주식 전용으로 바꾸지 않으며 미확인 유형도 표시한다.
- 시장 캘린더와 지표 계산 구간의 날짜 연속성을 확인한다. 장중 봉이나 누락 봉으로 전일 지표를 대체하지 않는다.
- 후보 전체, 제외 사유, 원본 행/사용한 가격 구간의 해시, 실제 확보 시각, 원본 시각이 있으면 원본 시각도 저장한다.
- 원본에 시각이 없으면 만들어 넣지 않는다. 현재 새로 확보한 사실과 과거 당시 확보 여부는 별개로 표시한다.
- 수집이 끝난 시각을 `snapshot_completed_at`으로 기록한다. 선택은 저장 완료된 한 스냅샷만 참조한다.
- 첫 완전한 수집을 고정한 이후 후보 수정은 해당 세션의 선택을 바꾸지 않는다. 오류 복구나 사후 수집은 별도 진단 기록으로 남긴다.
- 빈 후보 수집 성공, 미실행, 데이터 부족, 수집 오류는 서로 다른 상태다.

수집을 시작한 이후 확보한 입력으로만 선택한다. 그 이전 날짜를 채워 넣어 forward 실적으로 계산하지 않는다.
시장별 캘린더/후보 입력의 신뢰성이 확인되지 않으면 해당 시장은 관측 오류 상태로 남기고 자동 매수하지 않는다.

## 독립 계좌와 선택

각 시장에 다음 3개 계좌를 둔다. 계좌 식별자는 실험 버전·시장·규칙을 포함한다.

| 규칙 | 선택 | 초기 자본 | 일일 총 예산 | 동시 보유 상한 |
|---|---|---:|---:|---:|
| baseline_k1 | 전일 거래대금 내림차순 1종목 | 4,320,000원 | 540,000원 | 7종목 |
| random_k1 | 고정 난수 규약으로 1종목 | 4,320,000원 | 540,000원 | 7종목 |
| random_k3 | 고정 난수 규약으로 최대 3종목 | 4,320,000원 | 540,000원 | 21종목 |

- 각 계좌의 현금과 포지션은 독립적이다. 같은 종목의 시세 요청만 공유하고 자본/수량은 합치지 않는다.
- 난수 선택은 실험 버전·시장·세션·규칙과 고정 master seed `20260910`으로 결정한다. Python 프로세스별 hash에 의존하지 않으며 결과와 seed를 저장한다.
- 각 계좌가 이미 보유한 종목을 제외하고 선택한다. 동일 계좌의 동일 종목 중복 보유는 금지한다.
- 3종목보다 적으면 실제 선택 수로 일일 예산을 나눈다. 수량 부족/미체결 배정액을 다른 종목에 재분배하지 않는다.
- 정수 수량과 비용을 적용한다. 비싼 선택 종목이 매수 불가능하다고 차순위로 교체하지 않는다.
- 하루 예산은 첫 선택 시점에 확정한다. 이후 당일 매도대금으로 추가 진입하지 않는다. 현금 차입은 금지한다.
- v1은 규칙별 실제 관측 경로 하나를 쌓는다. 무작위 하나의 결과를 200개 독립 대조군처럼 표시하지 않는다. 과거 비교 도구의 난수 분포와 별도 표시한다.

## 실행 시점과 시세 품질

시장별 정규 세션만 대상으로 하며 NXT/시간외 거래는 추가하지 않는다. 기존 시장 캘린더와 현지 개장 시각을 사용하므로 US 서머타임을 KST 고정 시각으로 가정하지 않는다.

- 개장 후 5분부터 45분까지를 v1 신규 진입 창으로 고정한다. 첫 유효 수집/선택 이후 판단 시각보다 앞선 시세로 체결하지 않는다.
- 진입 창 전에 수집이 가능하면 미리 스냅샷을 준비할 수 있지만 가상 체결은 창 안에서만 한다.
- 진입 창을 놓치면 `ENTRY_WINDOW_MISSED`를 기록한다. 현재 시각으로 과거 시가 체결을 만들어내지 않는다.
- 실행 시세 관측은 기존 읽기 전용 시세 공급을 사용한다. 선택/보유 티커만 요청하고 같은 틱의 중복 요청을 합친다.
- 수집 완료 후 새로운 관측을 요청하고 요청/응답 시각·공급자·가격 종류·거래소 시각(제공 시)을 저장한다. 응답을 새로 받았다는 이유만으로 거래소 시세가 신선하다고 가정하지 않는다.
- 기준은 정상 유한 양수가, 거래 세션 일치, 검증 가능한 가격 관측 시각의 나이≤60초다. 미충족 또는 시각 불명은 `NO_VERIFIED_QUOTE`이며 가상 매수/청산하지 않는다.
- 60초 기준은 이 신규 비교 실험에만 적용하며 기존 ETF 패닉 레인의 stale 설정을 변경하지 않는다.
- 가격 종류가 체결가/최종가이면 `LAST_PRICE_PAPER`로 표시한다. 매수·매도 호가와 실제 체결/체결 가능 수량을 확인했다고 주장하지 않는다.
- 시세 실패는 진입 창 안에서 다음 관측 주기에 재시도하되 선택 목록을 바꾸지 않는다. 창이 끝나면 미체결/기권으로 확정한다.
- US 비교 계좌의 원화 환산은 고정 1,390원이며 이 값을 모든 규칙에 동일 적용한다. 실제 환율 손익 포함 성적은 아니다.

시세 공급 어댑터가 위 시각 검증을 충족하지 못하면 대시보드에는 관측/시세 부족으로 표시한다. 매수 건수를 만들기 위해 품질 기준을 자동 완화하지 않는다.

## 평가와 청산 계약

세 규칙에 동일한 청산 계약을 적용한다. 과거 일봉 시가 체결 연구와 구분되는 `forward_quote_v1` 계약으로 표시한다.

- TP: 관측한 신선한 가격이 진입가 대비 +12% 이상일 때 해당 관측 가격으로 가상 청산한다. TP 가격으로 소급 체결하지 않는다.
- SL: 현지 정규장 마감 전 15분 창에서 관측한 신선한 가격이 진입가 대비 −25% 이하일 때 가상 청산한다.
- US BE: 전 세션까지 관측한 최고 수익률이 +4% 이상이고, 마감 전 15분 창의 신선한 가격이 진입가 이하일 때 청산한다. KR에는 BE를 적용하지 않는다.
- 만기: 실제 진입 세션 포함 7번째 시장 세션의 마감 전 15분 창에서 신선한 가격으로 청산한다.
- 같은 관측에서 중복 조건이면 TP → SL → BE → 만기 순으로 사유 하나를 기록한다.
- 청산에 필요한 시세가 없으면 `EXIT_PENDING_QUOTE`와 초과 보유 상태를 표시한다. 재가동 시 현재 세션의 첫 유효 가격으로 지연 청산하고 예정 시각과 지연을 기록한다.
- 장중 평가 시세가 오래되면 마지막 평가일시를 유지하고 stale 표시한다. 과거 일봉 고가로 놓친 TP를 되살리지 않는다.
- 장 마감은 평가 기준일이지 소급 체결 허용 시각이 아니다. 운영 중단 구간은 표본 완전성 결손으로 기록한다.

비용은 원매수 금액 기준 KR 왕복 0.25%, US 0.50%다. 진입 시 절반을 차감하고 청산 또는 미청산 평가 시 나머지 절반을 반영한다.
`NAV = 현금 + 보유 평가액 − 미지급 청산 비용`이며, 초기 자본 대비 NAV 변화는 청산+미청산 비용 후 손익과 대사한다.
실현 손익만으로 승률/수익성을 판단하지 않는다. 충분한 보유기간이 지난 코호트 수, 미청산 수, stale 수와 누락 세션을 함께 표시한다.

## 저장소·재시작·오류 격리

신규 전용 SQLite `data/shadow/selection_forward.db`를 사용한다. 기존 가상 북 DB, 실계좌 상태, `phantom_positions.json`은 읽거나 쓰는 회계 원장으로 사용하지 않는다.

필수 테이블 역할:

- experiments: 버전, 고정 파라미터, 코드/설정 지문, 시장별 관측 시작 시각.
- sessions/snapshots: 세션 수집 상태, 입력 원문 또는 검증 가능한 참조, 해시, 확보 시각, 결손.
- decisions/intents: 전략·세션의 선택과 배정액, 미체결/기권 사유. UNIQUE 제약으로 선택 중복을 방지한다.
- positions/accounts: 전략별 독립 현금·보유. 실계좌와 연결 키를 공유하지 않는다.
- events: 가상 진입·가상 청산·오류·기권의 불변 기록. event id/intent id로 중복을 방지한다.
- valuations/heartbeat: 계좌 평가 시각, 데이터 신선도, 처리 상태.

선택 확정 및 체결 기록과 계좌 변동은 각각 단일 트랜잭션으로 처리한다. 외부 시세 I/O 중 쓰기 락을 유지하지 않는다.
복수 호출/재시작이 동일 의도를 처리해도 한 번만 현금을 차감한다. 이벤트와 상태가 불일치하면 신규 진입을 중단하고 대사 오류를 표시한다.
SQLite WAL과 짧은 busy timeout을 사용한다. 대시보드는 읽기 전용 연결이며 잠금 실패 시 이전 자료와 실패 시각을 표시한다.
봇 경로는 15초보다 자주 새 관측 작업을 시작하지 않으며 비동기/별도 작업으로 격리한다. 한 주기가 끝나기 전에 다음 주기를 겹쳐 실행하지 않고 대기열을 무한 누적하지 않는다.
시세 요청은 기존 공급자별 공용 rate limit과 타임아웃을 따른다. 요청 한도를 소진하면 해당 시세는 부족으로 남기며 주문 경로의 요청 예산을 우회하거나 설정을 늘리지 않는다.
현재 진행 중인 작업·원장·실주문 설정은 유지하고, 초기화/원장 삭제/기존 데이터 변환을 수행하지 않는다.

## 대시보드

`/virtual`에 “선택 비교 — 신규 SHADOW” 패널을 추가한다. 기존 가상 북/유령 수익률을 덮어쓰거나 합산하지 않는다.

- 상단: 시장·실험 버전·최초 관측 시각·최근 수집/평가 시각·heartbeat·시세 품질·SHADOW ONLY 표기.
- 계좌 비교: 초기 자본, 현금, 보유 평가액, 비용 후 NAV/수익률, 최대 낙폭, 투자 노출, 청산/미청산/성숙 코호트 수.
- 오늘 선택: 종목, 선택 근거/seed, 판단 시각, 가상 체결 시각/가격/수량, 시세 공급자, 미체결/기권 사유.
- 보유/청산: 진입·평가·청산가, 비용, 수익률, 보유 세션 수, 청산 사유, stale/지연 청산 경고.
- 입력 상태: 수집 성공 0건, 입력 부족, 미실행, 진입창 초과를 구분한다.
- 과거 재생 결과는 “연구” 영역에 남긴다. 신규 실적이 없는 경우 `첫 유효 관측 대기`이며 0% 성공 성적처럼 표시하지 않는다.
- HTML은 데이터 문자열을 escape한다. 원문 전체나 인증정보를 API 응답에 노출하지 않는다.

자동 승격 버튼이나 실주문 설정 변경 기능은 추가하지 않는다. 대시보드는 기존 갱신 주기를 활용하며 조회는 상태를 변경하지 않는다.

## 구현 완료의 검증 기준

1. 동일 입력·seed에서 재시작 후 동일 선택. 전략별 자본·동일 종목 포지션이 섞이지 않는다.
2. 동시 호출/중복 실행/저장 중 예외에서도 중복 체결이나 현금 이중 차감이 없다.
3. 후보 없음·수집 실패·지표 누락·진입창 초과·오래된 시세가 각각 화면/원장에 남는다.
4. 미래 입력/과거 시가의 소급 체결이 거부된다. 휴장과 US 서머타임을 테스트한다.
5. 정수 수량, 비용, 현금 부족, 당일 매도대금 재진입 금지, 3종목 미만의 예산 처리를 검증한다.
6. TP/종가창 SL/US 전일 BE/D7 및 시세 없는 만기의 지연 청산을 통제 시계로 검증한다.
7. 보유 평가와 청산+미청산 손익이 계좌 NAV와 대사한다. 오래된 시세는 정상 최신 시세로 표시되지 않는다.
8. 주문 API를 호출할 수 없는 어댑터 경계를 테스트하고 기존 봇/유령/대시보드 회귀 테스트를 실행한다.
9. 별도 테스트 저장소로 수집→선택→가상 체결→평가→청산→API의 통합 검증을 수행한다.
10. 운영 반영 전 프로세스/명령/스케줄을 확인하고 필요한 프로세스만 재시작한다. 주문 스위치 변경 없이 heartbeat/API/첫 수집 상태를 확인한다.

장이 닫혔거나 유효 시세가 없는 시점에는 “수집/실행 연결 완료, 첫 유효 체결 대기”로 보고한다. 테스트 체결을 운영 forward 원장에 넣지 않는다.

## 구현 순서와 비포함 범위

독립 원장/회계 → 수집 스냅샷/선택 → 시세·봇 실행 연결 → 대시보드 → 통합·재시작 점검 순으로 진행한다.
상세 작업별 계획과 테스트 목록은 이 설계 문서 검토 후 작성한다.

신규 악재 필터, 새 매매 전략, 뉴스 유료 공급 계약, 실주문, 과거 체결 복원, 기존 유령 엔진 개편, NXT 확장, 자동 승격은 포함하지 않는다.
